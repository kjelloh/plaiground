## What this is

cratchit is a C++ bookkeeping app for a Swedish limited company (aktiebolag).
Read `SPEC.md` for goals and current milestone, and `GLOSSARY.md` for naming.
Reference material (file format specs, SKV rules) lives in `_docs/` — see `_docs/README.md`.

## Tech stack

- Language: C++23 with best practices and safe code over efficient.
- Build: CMake, some established version
- Compiler: Platform default (cross platform enabled tool chain)
- Tests: GoogleTest
- Dependencies: Prefer vanilla implementation or Conan Package where appropriate

## Code conventions

- Naming: snake_case for variables and functions. CamelCase for types. Member 'm_' prefixed
- Use English identifiers; map Swedish domain terms via `GLOSSARY.md`.
- Money: Use dedicated Amount type that is integer 'cents' based
- Error handling: Use std::expected or error codes where appropriate. Exceptions for exceptional results.

## Data folders and privacy

| Folder | Content | In git? |
|---|---|---|
| `_sie_in/` | Real SIE exports from Fortnox (input) | No — local only |
| `_eskd_irl/` | Real eskd files that were sent to SKV | No — local only |
| `_sie_out/` | SIE files written by cratchit | No |
| `_to_skv/` | eskd files generated by cratchit | No |
| `.cratchit/` | cratchit's own persistent state | No |
| `_docs/` | Public specs and reference notes | Yes |
| `testdata/` | Anonymised example files for tests | Yes |

- Never copy real data (org number, names, amounts, voucher texts) into committed files.
- Tests that need real files must skip gracefully when the files are absent.

## Working style

- Small steps: one failing test, then the code to make it pass.
- Small files with single class or domain related code.
